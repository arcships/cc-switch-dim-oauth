# DimAgent for CC Switch

<img src="page/icon.png" width="72" alt="DimAgent">

**这是一个需要单独启动的本地桥接程序。它通过服务商导入链接接入 CC Switch，不能在 CC Switch 里点「安装插件」直接加载。使用期间必须保持本程序运行。**

### 不是直接安装插件吗？

不是。下载这个仓库、运行程序，再从账户页把供应商导入 CC Switch，才是本项目目前的使用方式。不要把仓库地址填到插件或 Skills 管理页面；登录入口也不会自动出现在 CC Switch 的「授权中心」。

CC Switch 当前支持导入服务商地址、Key 和模型配置，但没有开放 Magpie 那样的外部 OAuth 服务商插件接口。本程序负责 DimAgent 登录和自动续期，CC Switch 负责保存供应商配置。要做成 CC Switch 内置的 DimAgent 登录入口，需要修改 CC Switch 本体；本仓库没有实现这种原生接入。

如果你只接受「在 CC Switch 里安装一次，不额外运行程序」的体验，目前这个项目不满足这个要求。

### 用起来有哪些步骤？

```text
首次使用
  下载项目 → 启动本地程序 → 浏览器登录 DimAgent
  → 选择模型和客户端 → 生成导入链接
  → CC Switch 确认导入 → 切换供应商或添加到客户端配置

以后使用
  启动本地程序 → 使用已导入的供应商

停止使用
  停止本地程序 → 该供应商暂停可用，配置和登录信息仍保留
```

本项目提供模型目录、推理强度与 ZDR 展示、套餐和用量查询、购买续期入口，以及确认后执行的额度重置。用量和重置在浏览器账户页操作，不在 CC Switch 卡片内操作。

### 第一次怎么安装和启动？

先准备好 [Git](https://git-scm.com/downloads)、[Bun](https://bun.sh) 和 [CC Switch](https://github.com/farion1231/cc-switch/releases)。已在 macOS 安装版 CC Switch 4.0.25 上验证导入和模型拉取；其他版本及系统尚未完成实机验证。

在终端执行：

```bash
git clone https://github.com/arcships/cc-switch-dim-oauth.git
cd cc-switch-dim-oauth
bun install --frozen-lockfile
bun start
```

看到 `DimAgent: http://127.0.0.1:3489` 后，在浏览器打开 [DimAgent 账户页](http://127.0.0.1:3489)。终端暂时不要关闭。

`bun install` 只安装这个本地程序需要的依赖，不会把它安装到 CC Switch 内部，也不会自动添加供应商。本项目通过 GitHub 分发，未发布 npm。

### 怎么登录 DimAgent？

在账户页选择站点，点击「登录」，再点「前往授权页面」。在 DimAgent 的网页中完成授权，然后回到账户页；页面会自动显示登录结果。

这里使用的是 DimAgent 的 OAuth 登录。无需把账号密码、真实 access token 或 refresh token 复制到 CC Switch。CC Switch 导入框里的 Key 是本地程序生成的连接 Key。

每个站点保留一个账号，同一站点重新登录会替换旧账号。登录后程序会在需要时自动续期；授权失效时，回到账户页重新登录。

### 怎么把模型导入 CC Switch？

1. 在账户页选择模型和客户端。接口按模型目录提供的选项选择；模型请求 ID 会完整保留。
2. 使用 Codex 的 OpenAI 类接口时，可以选择目录明确提供的推理强度；留空表示使用客户端默认行为。其他组合不通过导入链接设置推理强度，按客户端自身的能力配置。
3. 点击「生成导入链接」，再点「打开 CC Switch 导入」。如果浏览器弹出「打开 CC Switch？」提示，选择打开。
4. 在 CC Switch 确认框核对模型、接口和 `http://127.0.0.1:3489/...` 地址，然后点击「导入」。CC Switch 会提示该地址是本机服务，这是本项目的正常连接方式。

**确认导入只保存配置，是否立即启用由确认框里的开关决定。本项目默认关闭这个开关。** 不同客户端接下来的操作不同：

| 客户端 | 导入后怎么使用 |
| --- | --- |
| Codex、Claude Code | 到对应客户端的供应商列表，找到 DimAgent，点击「切换 / Switch」。如果显示「需要路由 / Needs routing」，按 CC Switch 提示启用「路由 / Routing」。 |
| OpenCode | 在确认框打开「导入后添加到 OpenCode 配置」，或者导入后在供应商列表把它添加到配置。显示「已添加 / Added」后，在 OpenCode 里选择对应模型。 |

Codex 原生使用 Responses，Claude Code 原生使用 Messages。如果所选模型提供的是 OpenAI Chat Completions，CC Switch 会显示「需要路由」，需要由它转换格式；这不代表导入失败。使用这种路由时，也要保持 CC Switch 运行。

目前支持 Codex、Claude Code、OpenCode 的导入入口。Gemini 原生接口的模型请选择 OpenCode。

### 以后每次都要重新安装、登录和导入吗？

不用。回到已经下载的项目目录，启动程序即可：

```bash
cd cc-switch-dim-oauth
bun start
```

然后继续使用 CC Switch 里已保存的供应商。有效的登录会被保留，不需要每次重新授权。浏览器账户页可以关闭；运行 `bun start` 的终端需要保持开启。

按 `Ctrl+C` 可以停止程序。停止后，指向它的供应商就无法连接；再次启动后可以继续使用。关闭 CC Switch 不会替你启动或停止这个程序。本项目暂未提供自动启动服务。

### 模型目录会自动更新 CC Switch 吗？

账户页点击「刷新模型」会重新读取当前账号的模型目录，但不会自动覆盖 CC Switch 已导入的卡片。可以重新导入需要的模型，或者在 CC Switch 编辑供应商时使用「拉取模型 / Fetch Models」。

每次导入会新增一张供应商卡片；删除旧卡片需要在 CC Switch 中操作。模型的显示名称、可用推理强度和 ZDR 以刷新后的目录为准，已有卡片备注中的 ZDR 只是导入时的记录。

### 用量在哪里看？

回到 [账户页](http://127.0.0.1:3489)，点击「刷新」。这里显示套餐、限流窗口和功能用量。

「账户剩余」包含套餐余额，不要把它和套餐总量相加。没有提供总量的额度只显示余额，不显示使用百分比。CC Switch 卡片暂时不会自动显示这份用量。

### 怎么购买或续期？

点击账户页的「购买 / 续期」，或直接打开 [订阅管理](https://dimagent.cn/console/subscription)。想先看看套餐，打开 [套餐价格](https://dimagent.cn/console/pricing)。购买和付款都在官方控制台完成。

### 怎么重置额度？

在账户页选择「重置限流窗口」或「重置月度额度」。先核对账号、套餐、订阅和可用次数，再点「确认并重置」。确认后会消耗一次对应的重置次数，无法撤销。

如果网络中断，在同一个确认框里重试；不要重新发起一份重置。同一个确认的重试会复用原来的幂等标识。退出程序会丢失未完成的确认，此时请先刷新用量，确认上一次是否已生效。

### CC Switch 卡片为什么没有 DimAgent 图标？

账户页已经使用 DimAgent 原图。CC Switch 的导入图标地址要求是公网 HTTPS，不能直接使用本地图片地址；可以在编辑供应商时上传本项目的 `page/icon.png`。

### 登录失败、端口被占用或导入后连不上怎么办？

- 账户页打不开：先看运行 `bun start` 的终端是否还在，正常地址是 `http://127.0.0.1:3489`。
- `3489` 被占用：可能已经启动了一份本程序。先打开账户页确认，不要重复启动。
- 登录时 `54322` 被占用：这是固定授权回调端口。Magpie 等使用同一端口的登录窗口会冲突，结束另一个登录流程后重试；不要修改回调地址。
- 导入后还不能选模型：确认已经切换供应商，或已经把 OpenCode 供应商添加到配置；按客户端要求重启或重新打开客户端。
- 显示「需要路由」：按 CC Switch 提示开启路由，并保持 CC Switch 与本程序都在运行。
- 登录已过期：回到账户页重新登录。不要把网页账号密码或真实令牌手动填到 CC Switch。

### 登录信息保存在哪？怎么退出或清理？

保存在 `~/.local/share/cc-switch-dim-oauth/`，凭据文件只供当前用户读取。点击账户页的「退出登录」会删除所选站点的本地凭据；服务器上的授权管理由 DimAgent 控制台负责。退出登录不会删除 CC Switch 中的供应商卡片。

停止程序后可以删除这个目录，但会同时清除登录和本地连接 Key。之后需要重新登录并重新导入供应商；旧卡片保存的 Key 将不再可用。不要分享或提交这个目录。

要使用隔离目录，可以从项目目录运行：

```bash
DIM_CC_STATE_DIR="$PWD/.state" bun start
```

### 目前测试到什么程度？

已通过模拟登录、续期、目录、流式转发与重置流程测试，并在本机安装版 CC Switch 4.0.25 中验证了从浏览器唤起导入、Codex 的完整模型 ID 与推理强度保留、原生模型拉取，以及 OpenCode 配置写入。

实机导入测试使用隔离配置和模拟 DimAgent 账号，没有调用付费模型或消耗真实重置次数。两站真实授权参数已通过匿名预检，但真实账号登录、续期和付费模型生成尚未完成端到端实测；不能把模拟测试当作真实服务全流程已经验证。

开发检查命令：

```bash
bun test
bun run check
```

详细证据见 [验证记录](docs/verification.md)。
